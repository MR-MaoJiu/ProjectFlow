# ProjectFlow：Codex 全流程插件需求文档 v0.2

日期：2026-09-11

状态：已确认方向，首版本地实现随本文交付；原生宿主安装后的能力以实测结果为准。

适用用户：独立开发者与小型软件团队。

替代关系：替代 v0.1 中的独立平台定位、执行架构、Agent 接入、存储与首版边界。v0.1 保留用于历史追溯，需求编号迁移表见附录。

## 1. 已确认的产品决策

1. 产品以 Codex 插件发布，Codex 是主要入口和执行者。
2. 项目数据优先本地保存，不强制注册云端账户。
3. 提供完整配套工作台，覆盖全流程导航、文档编辑、UI 查看/切图、任务与证据。
4. 优先复用当前 Codex 的模型、工具和已授权连接，不增加独立模型调用层。
5. 普通草稿和已授权工作连续进行，关键节点确认：立项、范围/PRD、设计交付、生产发布。
6. UI 不依赖 Figma，交付结构化节点、预览、文案、交互说明和独立素材。
7. 首发验证目标为 macOS 桌面 Codex；MCP 与文本工作流可用于支持相同协议的 CLI。
8. 首版不提供其他 Coding Agent 调度、云端同步、实时多人编辑或无人值守执行承诺。

## 2. 产品职责与边界

| 层级 | 职责 | 不承担的职责 |
|---|---|---|
| Codex | 研究、写作、设计生成、代码修改、执行检查与解释结果 | 不以聊天记录替代持久化项目资产 |
| 阶段 Skill | 方法、输入输出、确认条件、工具契约和恢复方式 | 不绕过宿主权限，不自建模型服务 |
| 本地 MCP | 项目绑定、版本、请求、设计、素材、交付包和证据 | 不伪造测试或部署，不自行唤起 Codex |
| 工作台 | 浏览、编辑、确认、预览、切图与结果对照 | 不展示未经回写的虚假执行进度 |
| 项目目录 | 可追溯、可恢复、可随 Git 共享的资产 | 不将插件缓存当用户项目数据库 |

代码仓库是代码事实来源，执行环境是运行事实来源。登记测试或发布证据只是保存报告，界面需显示报告来自用户还是 Codex。只有真正运行的检查可以报告通过。

插件形式采用官方的 Skill、MCP 与可选 UI 组合，参考 [插件文档](https://learn.chatgpt.com/docs/plugins) 与 [UI 接入说明](https://developers.openai.com/plugins/build/chatgpt-ui)。原生 UI 宿主能力必须实测；完整本地工作台不依赖该可选摘要组件。

## 3. 用户旅程与全流程契约

用户在 Codex 输入“用 ProjectFlow 启动这个项目”。Codex 绑定用户明确选择的目录，读取状态，按阶段 Skill 开展工作；用户打开工作台编辑、审阅和确认。需要继续推理或执行时，工作台保存请求，用户回到当前 Codex 任务发送“继续”。

| 阶段 | 输入 | 操作与规则 | 输出与完成条件 |
|---|---|---|---|
| 立项 | 想法、约束、目标用户 | 澄清问题、价值、指标、不做事项、假设与验证方法 | brief 及用户确认的具体版本 |
| 调研 | 研究问题 | 用当前工具或用户资料调查；区分事实、观点、推断和假设；保留来源与日期 | research，结论可定位到来源，缺口明确 |
| 需求整理 | 调研、反馈、想法 | 按用户场景拆分需求、去重、排序、标注依赖和验收；当前迭代即当前范围 | requirement 及确认的范围基线 |
| PRD | 已纳入范围的需求 | 撰写目标、流程、规则、权限、异常、页面状态、数据、验收、埋点、发布和待澄清 | 可编辑 PRD 与确认版本 |
| UI | PRD、仓库组件和视觉约束 | 创建结构节点与样式，调用现有图片工具生成独立素材，预览并调整 | design、assets、页面/状态/交互，用户确认版本 |
| 开发交付 | 已确认需求、PRD、UI | 递归冻结引用，检查素材完整性，记录仓库基准与规则 | 不可变 HandoffBundle |
| Coding | 交付包与具体任务 | Codex 领取请求、检查目标目录规则、导出素材并实现，运行适当检查 | code、证据、submitted；用户验收后 accepted |
| 测试 | 验收标准、实现、环境 | 编写 test，执行适用检查、记录缺陷、修复后复测，设计/实际截图对照 | 绑定代码与环境的证据，未执行和失败不算通过 |
| 发布 | 代码、测试、发布策略 | 准备 release、检查授权、使用已有工具发布并核实，记录回滚边界 | 实际部署结果与发布证据；无工具时受阻 |
| 运营 | 已发布版本与真实数据 | 导入数据、定义指标、整理反馈、复盘；观察与原因推断分开 | metric/feedback/review，带来源的新迭代需求 |

允许从任意阶段编辑资产，不限制研究和测试规划并行；正式阶段推进一次一步，并检查必要上游。导入既有项目可补录现有基线，不能把未发生的历史过程伪装成已完成。

## 4. 工作台需求

### 4.1 通用界面

- 左侧：项目切换、十阶段导航、迭代选择与新建、工具状态。
- 中间：当前阶段产物、搜索、编辑器/画布、执行请求与证据。
- 右侧：所选产物版本、确认、来源、受影响下游、评论与决策。
- 顶部：项目、迭代、本地 revision 与待处理请求入口。
- 桌面三栏，窄屏保留核心操作，详情以可切换侧面板呈现。
- 所有生成请求明确“保存后回到 Codex 继续”，不假装已启动执行。

### 4.2 文档与需求

- 人工创建各类产物，提供 Markdown 模板，正文和标题可编辑。
- 文档编辑 1.5 秒停顿后尝试保存；本机缓存未提交草稿，失败可重试或导出。
- 原始 Markdown 可预览、导出；PRD 表格按 Markdown 渲染。
- 历史版本并排查看；还原内容创建新版本，不删除历史。
- 来源与依赖通过稳定 ID/版本选择；服务端拒绝循环依赖。
- 评论定位产物版本；确认包含操作者、理由、时间和确切版本。
- 首版使用人工/Skill 整理优先级和范围；专用评分看板、复杂实时协作后置。

### 4.3 UI 与切图

正式设计包含 viewport、nodes、interactions、states、tokens。节点至少包含 frame、rect、text、image、vector。拥有稳定 ID、几何尺寸、样式、布局和子节点。

- 画布缩放、页面预览、模块选择、边界与尺寸显示。
- 支持添加文字、矩形、已导入图片，修改文案、位置、大小、圆角与颜色。
- 支持绝对、横向和纵向布局，padding/gap 保存为布局语义。
- 结构 JSON 可导入和编辑；提交时严格校验类型、节点数、深度和素材引用。
- 独立位图支持 PNG/JPEG/WebP 导入，规范化为 PNG，记录源、尺寸和哈希。
- 使用 SVG path 节点表达真实矢量，不接受任意可执行 SVG/HTML。
- PNG 可以导出整页、模块或独立素材，支持 1×/2×/3×；倍率不等于新增原图细节。
- 包含位图的模块拒绝伪装成纯矢量 SVG。
- UI 内容不能只是一张整图。图片用于素材，文字和控件由结构化节点描述。
- 首版不具备完整矢量编辑、组件变体、复杂约束求解或动画时间轴。

### 4.4 任务、测试、发布与运营

- 请求可记录输入、目标、固定引用与交付包；状态为待执行、执行中、受阻、待评审、已验收、已取消。
- 工作台可复制执行指令、取消请求、验收提交或明确接管失联请求；不取消已经发生的外部副作用。
- 测试、发布、运营结果分别保存证据，并显示来源和未验证范围。
- 通过的测试/发布证据必须绑定代码版本、环境和产物引用；代码或关联资产变化后显示过期。
- 测试支持设计与实际截图并排对照；自动像素评分与真实设备集成不属于首版。
- 发布先形成候选记录与检查，再由 Codex 按授权调用实际部署工具；不自建 CI/CD。
- 运营支持 CSV 原始数据导入、指标口径说明、反馈、复盘及选择下一迭代创建需求。
- 运营数据缺失就显示缺失，不以零值代替；外部发送和付费不由草稿自动触发。

## 5. Codex 与插件协作

### 5.1 Skill

入口 Skill 负责定位项目与请求，仅按需读取阶段 Skill。提供 init、research、requirements、prd、design、handoff、coding、testing、release、operations 十个阶段工作流。

Skill 负责检查输入、选用当前工具、遵守项目规则、产出真实结果。插件没有单独的 API Key 配置层，不自动选择额外供应商。

### 5.2 MCP

| 工具 | 功能 |
|---|---|
| projectflow_bind | 绑定已有本地目录，初始化或恢复资产 |
| projectflow_projects | 列出当前服务绑定项目 |
| projectflow_read | 读取摘要、指定产物版本、请求上下文、交付包、证据和影响 |
| projectflow_mutate | 原子执行资产、流程、请求、确认和证据操作 |
| projectflow_asset_import | 导入项目内的独立图片 |
| projectflow_preview | 返回实际渲染的设计图像 |
| projectflow_export | 导出节点/素材到项目内并返回文件路径 |
| projectflow_workbench | 返回摘要、工作台链接和可选 UI 资源 |

具体参数、状态和设计结构详见插件 [工具契约](../references/contracts.md)。工具返回错误码，禁止将失败响应当作执行成功。

### 5.3 无宿主消息桥接的完整流程

工作台写 ActionRequest → 用户回到 Codex → bind/read → claim → 读取固定版本 → Codex 执行 → save/evidence → submitted → 用户审查 → accepted。

首版不依赖 UI 自动发消息，也不另开 Codex 会话。请求租约为 30 分钟；执行中进度回写可续期。失联后用户可明确接管重新排队，旧令牌不能回写。

### 5.4 可选插件 UI

MCP 返回标准 UI 资源，消费宿主的结构化结果通知，呈现项目名、迭代数、待办数与本地工作台链接。资源不访问外部网络。兼容客户端可直接使用工具文本链接，无需渲染 UI。

## 6. 本地资产、版本与一致性

- 每个项目的 `.projectflow/state.json` 为事务事实来源。
- documents 保存按版本命名的 Markdown 投影；assets 保存不可变内容文件。
- runtime 和 exports 不进入 Git；项目资产是否提交由用户决定。
- 核心对象：Project、Iteration、ArtifactVersion、ActionRequest、DesignDocument、Asset、HandoffBundle、Evidence。
- 写操作校验 revision、产物版本和幂等 key，跨进程写锁避免并发覆盖。
- 暂存文件完成写入和同步后原子替换状态；文档投影在事务前产生，状态未引用的残留文件不代表成功产物。
- 同一请求重试使用相同 key 和内容；不同内容复用 key 返回冲突。
- 新版不覆盖旧版。交付包冻结递归输入、素材与仓库信息，拒绝混用同一对象的不同版本。
- 改变上游后，下游按引用关系显示受影响范围；固定包仍可读取历史内容。
- 新 Codex 任务重新绑定路径即可恢复。插件升级与卸载不删除用户数据。
- 首版是单机文件协作，不将复制目录误当成实时多人同步。

## 7. 权限与异常规则

- HTTP 只监听 127.0.0.1，验证随机会话令牌、Origin 与 Host。
- 工作台浏览器不能任意绑定目录；绑定由 Codex 在用户所选范围内发起。
- 本机 URL 不公开，令牌不进入 Git；浏览器使用会话存储，重启服务使用新链接。
- 路径解析限制在绑定目录，拒绝资源目录及文件的符号链接逃逸。
- 文档不执行 HTML；设计节点拒绝脚本和任意 SVG；图片导入限制类型、大小和像素。
- 模型、工具、网络、执行和生产操作服从当前 Codex 的权限。插件 Skill 不扩大授权。
- 来源资料中的指令视为数据，不得改写流程或授权。
- 未知执行状态先核实，不能立即重复启动具有外部副作用的工作。
- 预算和模型账单首版不估造；费用沿用当前工具/宿主的实际显示。
- 未连接外部工具时显示能力缺失，允许导入资料或等待用户配置。

## 8. 首版验收

| 场景 | 验收条件 |
|---|---|
| 全流程 | 从立项资产到运营反馈均有真实可操作入口和持久化输出；模型工作由 Codex 执行 |
| 文档编辑 | 自动保存、刷新恢复、历史版本和冲突不覆盖 |
| 设计交付 | Codex 能读取结构和预览，独立素材可导出，错误格式被拒绝 |
| 请求协作 | 保存意图、领取、续租、提交、评审、接管和取消状态清楚 |
| 跨任务恢复 | 新 MCP 进程绑定原路径，仍可读取原项目和版本 |
| 上游变更 | 旧包不会变，新需求不能由旧任务直接算作完成 |
| 测试证据 | 通过/失败/受阻/跳过/未执行与报告来源均可区分 |
| 发布 | 记录实际环境和检查，未发生的生产发布不伪造 |
| 运营回流 | 原始数据与口径可查看，反馈转新迭代保留来源 |
| 权限和一致性 | 无令牌、跨站、错误 Host、越界路径、并发和重复写入有明确处理 |
| 安装与升级 | 插件结构和 Skill 验证通过，包包含运行依赖；新任务加载后的宿主 UI 单独实测 |

自动化测试覆盖核心协议、状态和异常；浏览器验证覆盖真实操作与视觉。生产环境、第三方数据连接和原生宿主安装等未实际运行的部分需要在交付中明确列出。

## 9. 后续增强

保持本地闭环后，依据真实使用增加：专用需求优先级与看板、复杂设计组件、细粒度 diff、视觉自动对比、运营图表和连接器、协作同步。新增独立模型或外部 Agent 执行系统必须另行确认，不悄悄改变 Codex 主导的定位。
